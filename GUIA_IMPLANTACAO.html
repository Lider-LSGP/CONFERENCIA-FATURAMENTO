Lider Limpe · Conferência documental

Sistema Streamlit de presença dos colaboradores nas relações de benefícios e nas folhas de ponto. Processamento local ao servidor, sem API de IA externa.

1. Publicar pelo GitHub

Crie um repositório preferencialmente privado e envie o conteúdo deste pacote na raiz. Não envie o ZIP como único arquivo: descompacte e envie app.py, engine.py, reports.py, security.py, requirements.txt, packages.txt, assets e as pastas de configuração.

No Streamlit Community Cloud, selecione repositório, branch e arquivo principal app.py. Use Python 3.11. requirements.txt instala as bibliotecas; packages.txt instala Tesseract com português e inglês.

2. Configurar acesso

Antes de processar dados reais, crie uma senha forte e gere seu hash em um computador:

python -m pip install -r requirements.txt
python security.py

Cole o hash retornado em Settings → Secrets da hospedagem:

[auth.users]
conferente = "pbkdf2_sha256$310000$SAL$HASH"

Gere outro hash para cada usuário. Nunca publique senhas ou secrets.toml. Sem configuração, o sistema bloqueia o acesso. Para usar localmente, coloque os mesmos Secrets em .streamlit/secrets.toml e execute:

python -m streamlit run app.py

O Tesseract deve estar instalado no sistema. Em Linux Debian/Ubuntu:

sudo apt-get install tesseract-ocr tesseract-ocr-por tesseract-ocr-eng

Em Windows, instale Tesseract e adicione sua pasta ao PATH. O Dockerfile também oferece instalação com OCR.

A senha do app é uma proteção básica, não um serviço de SSO. Para dados pessoais em produção, restrinja também o acesso na hospedagem, use HTTPS e avalie permissões, retenção, backups e controles LGPD. Community Cloud pode não ter recursos suficientes para muitos PDFs escaneados simultaneamente; servidor privado dimensionado é a opção recomendada para uso frequente.

3. Usar a conferência

Carregue vários PDFs/ZIPs, confira a categoria de cada arquivo e processe. A folha é a base. Empresa, CNPJ, contrato e competência não são fundidos. Para maior segurança, use um lote por empresa e competência. Se a empresa dos documentos não puder ser determinada num lote multiempresa, a entrega é bloqueada.

VA, saúde, odonto, seguro e Idesbre são exigidos para todos. VT depende da presença da rubrica de desconto; Sindicato depende de Sindilimpe. A presença de rubrica de desconto, inclusive de valor zero, ativa a exigência. Créditos de VA/VT com valor zero não confirmam concessão. Ajustes de regras são auditados.

Guarda-vidas: escolha GVBUS OU Alvorada ou exigir ambas. Outros cargos: GVBUS. Alvorada tem parser genérico conservador; não havia amostra específica desse fornecedor no lote recebido. Todo resultado desse layout exige revisão individual.

4. Identidade e revisão

CPF válido é prioritário. CPFs odontológicos com menos dígitos são completados com zeros e verificados pelos dígitos verificadores. Nome igual não sobrepõe CPF conflitante. Remoção de acentos, partículas e comparação de tokens ajudam na sugestão; abreviações, homônimos e proximidades não seguras vão à revisão. O índice textual não é probabilidade.

No painel, confira os colaboradores reconhecidos. Corrija as regras somente após ler a folha, com justificativa. Na revisão, selecione candidato, veja as páginas e confirme, registre ausência ou dispensa justificada. A validação em lote exige seleção e responsabilidade explícita; OCR e conflitos de CPF ficam fora desse atalho. Um mesmo registro não pode confirmar pessoas diferentes.

5. Ponto e OCR

O sistema examina todas as páginas. Nas sem texto, usa Tesseract e procura o campo Colaborador. Nome digitado costuma ser mais reconhecível que nome manuscrito; não há garantia de leitura de caneta. OCR sempre exige revisão humana. Quando o nome não é identificado, veja a imagem e vincule a página manualmente. Isso confirma somente a existência da folha de ponto, não horários, faltas, assinaturas ou jornada.

OCR de centenas de páginas pode demorar vários minutos e consumir memória. O lote aceita até 180 MB descompactados e cada PDF até 600 páginas; são proteções de entrada, não garantia de capacidade do servidor. O app não faz cache global de documentos e não envia PDFs a APIs externas. Fechar/reiniciar a sessão pode apagar os dados; exporte o JSON de revisão e recarregue o mesmo lote para continuar.

6. Exportar e enviar

O Excel interno traz resumo, matriz, divergências, abas por benefício, base da folha, auditoria de páginas/documentos e decisões. Contém informações pessoais e deve ficar restrito. O JSON preserva as decisões e ajustes de base, condicionado aos hashes do lote e às mesmas opções.

O pacote do cliente contém Excel minimizado e relatório HTML com CPF parcialmente mascarado, somente do escopo selecionado. O HTML pode ser impresso como PDF no navegador. PDFs originais e relações completas não são incluídos, pois podem expor outros contratos. Havendo pendências, só é possível gerar rascunho identificado como tal; erros de processamento bloqueiam a entrega. Não há envio de e-mail automático.

O sistema confere presença nas relações. Não faz conciliação financeira de boletos, cálculo de faturamento, validação fiscal, análise de cobertura contratual vigente ou apuração da jornada. Comprovante de pagamento sozinho não confirma que um colaborador consta da relação.

7. Testes

python -m pip install pytest
python -m pytest -q

Os testes usam dados sintéticos, não documentos pessoais. Os anexos reais usados na validação não fazem parte do repositório. Novos layouts exigem homologação antes do uso operacional.

Arquivos principais

app.py: interface e revisão; engine.py: parsing/OCR/comparação; reports.py: exportações; security.py: hashes de senha; tests: regressões; packages.txt: OCR; .github/workflows: testes automáticos.
